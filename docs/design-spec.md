# 意匠の決め方

## 方針

**対応する道路標識があるものは、標識令で定められた図案をそのまま使います。** 地図の上で
見たときに「見慣れた標識」であることが何より分かりやすいからです。

| 出所 | 数 | 何を使うか |
|---|---|---|
| 標識令の図案 | 44 | 別表第二の図案（`signs/`）を 64×64 に正規化 |
| 独自作図 | 29 | 標識が無いもの、または標識はあるが再現SVGが無いもの |

コードごとの出所は [icon-list.md](icon-list.md) の「出所」列にあります。

**「公式」とは呼びません。** 公式なのは図案（法令で定められたもの）で、`signs/` の
SVGファイル自体は政府配布ではなく、Wikimedia Commons の利用者が図案を再現したものです
（`PD-Japan-exempt`）。政府配布の図は
[e-Gov 法令検索の標識令](https://laws.e-gov.go.jp/law/335M50004002003)にありますが、
別表第二の図は JPEG のラスタ画像なので地図アイコンには使えません。

はじめは全部を独自に作図していましたが、**実物と並べたときに見慣れた形にならなかった**ため、
図案のSVGを取り込む方針に変えました。このSVGは文字がすでにパス化されているので、
`止まれ`・`50`・`3.3m`・`通行止` といった文字もそのまま入り、
ラスタライズ時にフォントを必要としません。

## 図案の取り込み

`signs/` に置いた SVG を `tools/import_signs.py` が `icons/<コード>.svg` にします。

- **パスには手を入れません。** ルート要素の `width` / `height` を 64 にし、
  `viewBox` が無ければ元の寸法から補うだけです（元の座標系はそのまま残ります）
- 出典を XML コメントで各ファイルの先頭に入れます
- `<text>` が混ざっていたら止めます（フォントに依存する配信物は作らない）

対応表は [`../data/sign_refs.csv`](../data/sign_refs.csv)。1つの標識を複数の
コードで共有することがあります（`3` と `81` は 325の3、`112`〜`114` は 323）。

意図して別の標識を当てたものもあります。

| コード | 交通規制種別 | 当てた標識 | 理由 |
|---|---|---|---|
| 7 | 車両通行止め(踏切) | 警戒標識 207のB（踏切あり） | 302 だと `5 車両通行止め` と同じ絵になり、地図で区別できない |
| 12 | 指定方向外進行禁止 | 311-B | 方向は設置ごとに違うので代表を1つ |
| 112〜114 | 最高速度 | 323（50km/h） | 速度は設置ごとに違うので代表を1つ。実際の値は属性で見る |

## 独自に作図するもの

次の29コードは独自作図です。理由はコードごとに
[`../data/handdrawn_reasons.csv`](../data/handdrawn_reasons.csv) にあります。

```
16 19 20 21 24 52 57 58 60 64 70 76 82 83 86
90 91 92 93 94 98 102 107 110 111 116 117 118 119
```

- **別表第二に標識があるが Commons に再現SVGが無い**（8コード）…
  `21` `24` `70` `92` `110` `111` `116`。SVGが公開されれば図案に差し替えられる
- **そもそも標識が無い**（21コード）… 道路標示・標示板で規定されるもの、
  信号機、JARTIC 独自の組合せ

地図で 20〜24px に縮んでも読めるよう、次の体系で描いています。

| 家族 | 台紙 | 例 |
|---|---|---|
| 路面標示 | 灰の路面に白（または黄）の線 | 停止線、中央線の変移、車両通行帯、導流帯、路側帯 |
| 指示 | 青の正方形 | 駐車可、優先本線車道、左折可 |
| 設備 | そのものの形 | 信号機（3灯） |

**独自作図では文字を使いません。** ラスタライズする環境にフォントが入っているかどうかで
結果が変わるためです（`tools/verify_icons.py` が `<text>` の混入を検査します）。

色は標識の図案に合わせています。

| 用途 | 値 |
|---|---|
| 赤 | `#ED1C23` |
| 青 | `#0066B3` |
| 白 | `#FFFFFF` |
| 黄（中央線） | `#F2C200` |
| 路面 | `#8A9199` |

## 小さくしたときの読みにくさ

図案をそのまま使うと、次のものは 22px では文字が潰れます。形と色で
「どの家族の規制か」は分かりますが、細かい種別までは読めません。

- `53` 追越し禁止・`69` 駐車余地・`100` 高齢運転者等標章自動車駐車可 — 補助標識の文字が付く
- `112`〜`114` 最高速度 — 数字が読めない（値は属性で見る）
- `4` 通行止め・`8` 歩行者通行止め・`14` 歩行者横断禁止 — 文字が付く

独自作図では、次のものが伝わりにくいままです。

- `91` 路面電車停留場 — 電車とホームに見えにくい
- `107` `118` `119` — 通行帯と矢印の組合せ同士の違いが小さい

## 網羅性の確かめ方

e-Gov の法令データ（[標識令](https://laws.e-gov.go.jp/law/335M50004002003)）から
別表第二の標識一覧を抽出し、Commons API で得た実在ファイル全件（407件）と
突き合わせました。ファイル名を推測して「無い」と判断するのは誤りやすく、実際に
`403`（駐車可）や `100` の取り違えはこの突き合わせで見つかりました。

抽出は正規表現によるもので、別表第二の全行を拾えているとは限りません。そのため
`data/handdrawn_reasons.csv` では、標識番号を確認できたものを `no_svg`、
確認できなかったものを `not_found` として区別しています。

## はみ出しの検査

独自作図では、矢印の先や線が **枠（64×64）や台紙（円・正方形・路面）の外**に出やすく、
出た分は配信物では切り落とされます。目で探すのはあてにならないので、機械的に測ります。

```bash
npm run bounds              # はみ出しているものを並べる
npm run bounds -- --strict  # 1つでもあれば異常終了する
```

viewBox を広げて描き直し、本来の 64×64 の外に色が乗っていないかを見ます。あわせて
台紙の形（円は r=27、正方形は 5〜59、路面は 3〜61）の外に出ていないかも数えます。
標識令の図案は台紙が枠いっぱいに描かれているのが正しい形なので、この検査にはかけません。

この検査で、路面の矢印（`58` `107` `118` `119`）が路面の外に出ていた、
右左折の方法（`57`）の矢印が枠外に出ていた、斜め横断可（`86`）の縞が大きく
はみ出していた、信号機（`98`）が右にずれていた、といった不具合を見つけて直しました。

## 突き合わせ

図案を使っているコードについて、取り込みが崩れていないかを機械的に確かめられます。

```bash
npm run compare              # signs/ の図案と icons/ を並べ、色の構成を比べる
npm run compare -- --strict  # ずれていたら異常終了する
```

独自に作図していた頃は、これで台紙の取り違え（歩行者向けの禁止標識を青の正方形に
していた、原付の右折方法の台紙を間違えていた等）を見つけて直しました。
いまは図案をそのまま使うので、ずれるのは取り込みが壊れたときだけです。

## 変えるとき

1. 図案を増やす → `data/sign_refs.csv` に行を足し、`signs/` に SVG を置く
2. 独自作図を直す → `tools/icons_lib.py` の部品か `tools/gen_icons.py` の `DESIGNS`
3. `npm run icons` でアイコンを作り直す（図案の取り込みも走る）
4. `npm run verify` で整合を見る
5. `npm run compare` で図案と突き合わせる
6. `npm run docs` で一覧を作り直し、`npm run build` でスプライトを作る

アイコンを増やすのは、JARTIC の仕様書で新しい規制種別が有効になったときだけです。
`data/codes.csv` は仕様書 表4 の写しなので、そこを直してから `npm run icons` を回すと
定義の無いコードで止まります。
