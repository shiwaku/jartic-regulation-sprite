# 意匠の決め方

## 方針

**対応する道路標識があるものは、標識令で定められた図案をそのまま使います。** 地図の上で
見たときに「見慣れた標識」であることが何より分かりやすいからです。

| 出所 | 数 | 何を使うか |
|---|---|---|
| 標識令の図案 | 44 | 別表第二の図案（`signs/`）を 64×64 に正規化 |
| 道路標示の図にもとづく作図 | 25 | 対応する標識が無い路面標示など。別表第六の実物の図を見て描く |
| 標識の図案にもとづく作図 | 1 | `70` 駐車可。標識403の意匠だが Commons に再現SVGが無い |
| 対応する標識・標示なし（独自） | 3 | `94` 左折可、`98` 信号機、`102`。ここだけがゼロからの作図 |

コードごとの出所は [icon-list.md](icon-list.md) の「出所」列にあります。

**「公式」とは呼びません。** 公式なのは図案（法令で定められたもの）で、`signs/` の
SVGファイル自体は政府配布ではなく、Wikimedia Commons の利用者が図案を再現したものです
（`PD-Japan-exempt`）。政府配布の図は
[e-Gov 法令検索の標識令](https://laws.e-gov.go.jp/law/335M50004002003)にありますが、
別表第二の図は JPEG のラスタ画像なので地図アイコンには使えません。

はじめは全部を独自に作図していましたが、**実物と並べたときに見慣れた形にならなかった**ため、
図案のSVGを取り込む方針に変えました。このSVGは文字がすでにパス化されているので、
`止まれ`・`50`・`3.3m`・`通行止` といった文字もそのまま入り、
ラスタライズ時にフォントを必要としません。

## 図案の取り込み

`signs/` に置いた SVG を `tools/import_signs.py` が `icons/<コード>.svg` にします。

- **パスには手を入れません。** ルート要素の `width` / `height` を 64 にし、
  `viewBox` が無ければ元の寸法から補うだけです（元の座標系はそのまま残ります）
- 出典を XML コメントで各ファイルの先頭に入れます
- `<text>` が混ざっていたら止めます（フォントに依存する配信物は作らない）

対応表は [`../data/sign_refs.csv`](../data/sign_refs.csv)。1つの標識を複数の
コードで共有することがあります（`3` と `81` は 325の3、`112`〜`114` は 323）。

意図して別の標識を当てたものもあります。

| コード | 交通規制種別 | 当てた標識 | 理由 |
|---|---|---|---|
| 7 | 車両通行止め(踏切) | 警戒標識 207のB（踏切あり） | 302 だと `5 車両通行止め` と同じ絵になり、地図で区別できない |
| 12 | 指定方向外進行禁止 | 311-B | 方向は設置ごとに違うので代表を1つ |
| 112〜114 | 最高速度 | 323（50km/h） | 速度は設置ごとに違うので代表を1つ。実際の値は属性で見る |

## 図案を使わず手で描くもの

次の29コードは手描きです。ただし**行き当たりで描いたものではありません。**
対応する道路標示が別表第六にあるものは、**e-Gov の法令データから図を取り出して
実物を見て**形を決めています（25コード）。`70` 駐車可は標識403の意匠にもとづき、
何も参照せずゼロから描いているのは `94` `98` `102` の3コードだけです。
根拠と標示番号は
[`../data/handdrawn_reasons.csv`](../data/handdrawn_reasons.csv)。

```
16 19 20 21 24 52 57 58 60 64 70 76 82 83 86
90 91 92 93 94 98 102 107 110 111 116 117 118 119
```

図の取り出し方は次のとおりです。

```
一覧  https://laws.e-gov.go.jp/api/2/law_data/335M50004002003?law_full_text_format=json
      → attached_files_info.attached_files[]（348点）
図    https://laws.e-gov.go.jp/api/2/attachment/{law_revision_id}?src=./pict/{ファイル名}
```

法令本文の別表第六の表構造（`TableRow` → `TableColumn` → `Fig`）から
「標示番号 → 図」を対応付けています。図は寸法線入りの製図（JPEG）なので、
アイコンとしては使えず、**意匠の参照にだけ使っています**。

実物を見て分かって直した例:

| コード | 実物（標示） | 直した内容 |
|---|---|---|
| 57 右左折の方法 | 111 は交差点内を曲がる軌跡の矢印 | 左右2本の直線矢印をやめ、曲がる軌跡にした |
| 58 進行方向別通行区分 | 110 は軸に「かえし」が付いたL字の矢印 | 扇状の直線矢印をやめ、L字にした |
| 19 立入り禁止部分 | 106 は角丸の輪郭の中を斜縞で埋める | 四角い枠をやめ、角丸の輪郭にした |
| 76 停止禁止部分 | 107 は枠の内側に短い斜線を並べる | ×をやめ、内向きの斜線にした |
| 86 斜め横断可 | 201の2 は交差点の四隅を斜めに横断する縞 | 平行な縞をやめ、×に交差する縞にした |
| 91 路面電車停留場 | 209 は軌道の脇の細長い島 | 箱とホームをやめ、軌道＋島にした |
| 92 停止線 | 203 は太い白線1本 | 余計な矢印を外した |
| 52・83 | 道路標示に**赤は使われていない** | 赤い斜線をやめた（52は黄の実線、83は白の横棒） |
| 15・16 中央線 | 205 の中央線は白 | 黄から白にした（黄の実線は 17 はみ出し禁止） |

**道路標示に赤は使いません。** 白（一部黄）だけで描きます。

### 実物と違うままのもの

| コード | 理由 |
|---|---|
| `21` `24` `110` `111` | 実物は路面に書かれた**文字**（「大型」「専用」など）。文字は使えないので、自動車・バス・自転車の絵で代えている |
| `116` 駐車方法の指定 | 実物は平行・直角・斜め駐車の3種（112・113・114）。駐車枠1つで代表させている |
| `107` `118` `119` | JARTIC 独自の組合せで、対応する単一の標示が無い |
| `94` 左折可 | 標示板（青地に白の矢印）。別表第六に該当が無い |
| `98` 信号機 | 標識も標示も無い。3灯の信号機で表している |
| `102` | 318（時間制限駐車区間）と補助標識の組合せ |
| `70` 駐車可 | 標識403 の意匠（青地に白のP）だが Commons に単体のSVGが無い |

**この一覧は精査中です。** どれをどう直すかは
[手描きの29アイコンを精査する](https://github.com/shiwaku/jartic-regulation-sprite/issues/1) にまとめています。

## 見分けにくい組み合わせ

手描き分では、意味が近いもの同士に次のように差を付けています。

| 組み合わせ | 付けた差 |
|---|---|
| `19` 立入り禁止部分 / `90` 導流帯 | どちらも斜縞。立入り禁止部分には白枠を付ける |
| `20` 車両通行帯 / `21` 車両通行区分 | 線だけ / 線＋自動車（区分は車種で分ける） |
| `24` 路線バス等優先通行帯 / `111` 専用通行帯 | どちらもバス。優先は破線、専用は実線で区切る（実際の標示の違い） |
| `107` 車両通行帯及び車両通行区分 | 線＋自動車＋直進の矢印（`21` に矢印を足したもの） |
| `58` 進行方向別通行区分 / `118` / `119` | 矢印3本だけ / 破線の通行帯＋矢印2本 / 実線の通行帯＋矢印2本 |
| `57` 右左折の方法 | 左右の矢印だけ（`58` は直進を含む3本） |
| `92` 停止線 / `93` 二段停止線 | 太い白線1本 / 2本 |

### 通行帯と乗り物の組み合わせ方（`21` `24` `110` `111`）

通行帯の線は端（x=9・55）に寄せ、乗り物は**路面色の下敷きの上に大きく**置きます
（`lane_vehicle()`）。はじめは乗り物を線の内側に収めていましたが、実際の地図
（Z16、実表示27px）で **`111` のバスが実線2本と融合して「H」にしか見えなかった**
ためです。下敷きの余白が乗り物と線を分離し、破線/実線の区別は線の全高で見えます。

乗り物そのものも、小さくても見分けられるようシルエットで差を付けています。
バスは窓の列を抜いた長い箱、自動車はキャビンの段が付いた形、自転車は太いリング2つ。

同じ検証で、`16` 中央線の変移の折れが読めなかったため、線を太く（5→7）
横ずれを大きく（16→28）しました。検証の記録は
[issue #1 のコメント](https://github.com/shiwaku/jartic-regulation-sprite/issues/1)にあります。

### 路面の矢印

実物の進行方向の矢印は L 字（直進してから曲がる形）ですが、20px では折れ目が
潰れて読めません。**根元から扇状に傾けた塗りの直線矢印**にしています。
通行帯の線と併せる `118`・`119` は、実物どおりの L 字矢印（`mark_arrow_l`）を
2本にし、端に寄せた線とかえしが重ならない位置に置きます。

はじめはストロークの折れ線で描いていましたが、丸いキャップで頭が団子状になり、
線と重なると人型に見えてしまいました。

## 網羅性の確かめ方

e-Gov の法令データ（[標識令](https://laws.e-gov.go.jp/law/335M50004002003)）から
別表第二の標識一覧を抽出し、Commons API で得た実在ファイル全件（407件）と
突き合わせました。ファイル名を推測して「無い」と判断するのは誤りやすく、実際に
`403`（駐車可）や `100` の取り違えはこの突き合わせで見つかりました。

抽出は正規表現によるもので、別表第二の全行を拾えているとは限りません。そのため
`data/handdrawn_reasons.csv` では、標識番号を確認できたものを `no_svg`、
確認できなかったものを `not_found` として区別しています。

## はみ出しの検査

手描き分では、矢印の先や線が **枠（64×64）や台紙（円・正方形・路面）の外**に出やすく、
出た分は配信物では切り落とされます。目で探すのはあてにならないので、機械的に測ります。

```bash
npm run bounds              # はみ出しているものを並べる
npm run bounds -- --strict  # 1つでもあれば異常終了する
```

viewBox を広げて描き直し、本来の 64×64 の外に色が乗っていないかを見ます。あわせて
台紙の形（円は r=27、正方形は 5〜59、路面は 3〜61）の外に出ていないかも数えます。
標識令の図案は台紙が枠いっぱいに描かれているのが正しい形なので、この検査にはかけません。

この検査で、路面の矢印（`58` `107` `118` `119`）が路面の外に出ていた、
右左折の方法（`57`）の矢印が枠外に出ていた、斜め横断可（`86`）の縞が大きく
はみ出していた、信号機（`98`）が右にずれていた、といった不具合を見つけて直しました。

## 突き合わせ

図案を使っているコードについて、取り込みが崩れていないかを機械的に確かめられます。

```bash
npm run compare              # signs/ の図案と icons/ を並べ、色の構成を比べる
npm run compare -- --strict  # ずれていたら異常終了する
```

独自に作図していた頃は、これで台紙の取り違え（歩行者向けの禁止標識を青の正方形に
していた、原付の右折方法の台紙を間違えていた等）を見つけて直しました。
いまは図案をそのまま使うので、ずれるのは取り込みが壊れたときだけです。

## 変えるとき

1. 図案を増やす → `data/sign_refs.csv` に行を足し、`signs/` に SVG を置く
2. 手描き分を直す → `tools/icons_lib.py` の部品か `tools/gen_icons.py` の `DESIGNS`
3. `npm run icons` でアイコンを作り直す（図案の取り込みも走る）
4. `npm run verify` で整合を見る
5. `npm run compare` で図案と突き合わせる
6. `npm run docs` で一覧を作り直し、`npm run build` でスプライトを作る

アイコンを増やすのは、JARTIC の仕様書で新しい規制種別が有効になったときだけです。
`data/codes.csv` は仕様書 表4 の写しなので、そこを直してから `npm run icons` を回すと
定義の無いコードで止まります。
